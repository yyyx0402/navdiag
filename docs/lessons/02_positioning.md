# 第二课：观测怎样变成位置

打开 `src/navdiag/positioning.py`，从 `solve_wls` 开始。

## 位置和时钟都是未知量

一颗卫星的修正伪距近似为：`rho = ||receiver - satellite|| + receiver_clock + noise`。伪距和时钟偏差都以米表示。因为接收机时钟有偏差，不能只用三颗卫星解三维位置。多星座模型为每个星座增加一个时钟未知量，至少需要 `3 + 星座数` 条独立观测，并且几何矩阵要满秩。

代码每次计算当前预测伪距与实际伪距的差，再用设计矩阵解一个小增量。不断迭代直到增量很小。`sigma_m` 较大的观测获得较小权重。Huber 版本在接近解后减小大残差的权重；大残差也可能来自未建模偏差，稳健法不是总会更好。

地球在信号传播期间旋转，`earth_rotation_correction` 将卫星位置转换到接收时刻的坐标。测试的无噪声例子检查是否能恢复已知接收机和时钟；它验证计算，没有证明真实数据的全部误差模型正确。

## 坐标与参考轨迹

ECEF 是以地心为原点的三维米制坐标。经纬高适合描述位置，ENU 则适合描述附近的东、北、上偏移。水平误差是 `sqrt(east_error² + north_error²)`，不是经纬度数值直接相减。

项目使用第一份成功GNSS解定义局部ENU原点。GSDC适配在有效支持范围内插值参考，跨大间隙不插值、不外推；UrbanNav按±0.05秒最近时间匹配并检查参考质量Q=1/2。两种参考策略分别记录，均只用于离线标签与评分，不传给求解器或作为模型特征。

## 当前真实分支与教学WLS

`positioning.py`用于模拟/GSDC的自有LS、坐标变换和几何测试。当前UrbanNav原始数据由独立GPL工具调用RTKLIB，根据广播星历运行GPS/北斗单频SPP，再提取观测特征；二者的算法/输入不同，分数不能直接池化。完整流程见[当前定位报告](../experiments/positioning_expansion.md)和[方法来源](../research/positioning_methods.md)。

## 练习

1. 阅读 `tests/test_positioning.py`，解释无噪声、多星座和退化几何分别检查什么。
2. 在复制的仿真例子中给一条伪距增加 30 m，比较等权、加权和稳健解。
3. 不要只观察位置误差：同时看残差、迭代次数和失败回退。
4. 找出 `gsdc.py` 中生成标签的位置，确认没有把参考坐标传给 `solve_wls`。
