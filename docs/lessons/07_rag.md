# 第七课：RAG怎样选择资料和控制上下文

先读 [knowledge.py](../../src/navdiag/knowledge.py) 的 `retrieve_knowledge`，再看 [semantic.py](../../src/navdiag/semantic.py) 与 [agent_context.py](../../src/navdiag/agent_context.py)。RAG的作用是找到可引用的资料，再让回答模型解释；它不训练新的GNSS识别器。

## 两类依据

当前实验数值由只读报告工具提供，例如模型Precision、位置RMSE和可用率。概念/方法由项目文档和有范围声明的研究摘要提供。论文使用的设备、指标与数据条件需要保留，不能把作者成绩写成NavDiag成绩。

项目资料来自明确的文档白名单，按章节切分，每段最多480字符并保留来源行号；20篇文献只包含原创摘要和元数据，不包含全文。实际段落数与版本见[RAG记录](../RAG_RETRIEVAL.md)。

## 从问题到片段

1. 规范少量已知术语或拼写变体，保留原问题供模型回答。
2. 用BM25/字符TF-IDF匹配关键词；有本地BGE时，同时计算向量相似度。
3. 检查相关性门槛，去除重复、限制每文档段数，取少量片段。Agent请求通常最多五条；不是扫描结果全量送入LLM。
4. `evidence_context`保留相关指标与证据映射，省略训练长曲线、完整阈值扫描等内容。
5. 模型收到问题和投影后的依据，最终按E1/E2等编号引用。

BGE权重和向量缓存位于本机，编码不消耗所配置LLM的API输入额度。top-k、每段长度和实验证据大小共同影响最终输入；字符数不是精确token数，实际用量以服务返回usage为准。

## 文献学习与问答的区别

[literature.py](../../src/navdiag/literature.py) 的 `reading_list`先按主题/难度过滤，再在研究摘要中推荐最多五篇；空问题可浏览全库。卡片提供学习指南和原文入口。指南不进入LLM检索段落；“用这个问题提问”只填表，不自动请求模型。

点开原文是使用者阅读行为，当前项目LLM没有自动联网搜索。工具Agent可改写查询并搜索本地资料，但不因此获得网站访问能力。

## 检索评测和回答评测

Hit@5检查目标来源是否进入前五，MRR检查首次命中位置；无关问题检查是否返回空结果。这些不能验证正文数字或因果解释。[GLM检查](../experiments/glm_quality.md)保留了“已实现/未来可实现”混淆和错误引用，说明找到来源仍需检查答案。

资料更新后用固定旧问题回归，不删除失败问题或改预期来源制造提升。真正独立评估需新增未参与修订的问题。

## 练习

- 查询“本项目Doppler速度从哪里来”，核对返回的是项目实现说明还是作者研究结果。
- 查询“HDOP很小是否保证没有NLOS”，检查回答是否把线索当保证。
- 查询一个无关日常问题，检查证据问答是否明确没有依据、是否跳过模型请求。
- 对比“比较定位精度”和“Doppler原理”两问的证据：当前数值应来自报告，原理应来自文档。

先在离线模式记录命中来源、工具和引用。无需为读懂RAG反复调用真实模型。
