# 第一课：特征、标签和数据划分

从 [nlos.py](../../src/navdiag/nlos.py) 的 `NLOS_FEATURES` 开始。主任务是：根据某颗卫星当前及可用历史观测，识别其LOS/NLOS状态。一条样本是“采集段 × 接收机 × 时间 × 卫星”，不等于整台接收机的位置。

## X 和 y

NLOS当前五项输入：

| 字段                      | 含义                              |
| ------------------------- | --------------------------------- |
| `cn0_dbhz`                | 载噪比，单位dB-Hz                 |
| `elevation_deg`           | 卫星仰角                          |
| `residual_normalized`     | 归一化伪距拟合残差                |
| `pr_rate_consistency_mps` | 观测变化与Doppler预测的一致性特征 |
| `cn0_std_dbhz`            | 同一卫星短期载噪比变化            |

标签来自独立参考：KLT使用鱼眼相机天空掩膜，UrbanNav使用独立位置与静态建筑图。已获准监督的观测中，NLOS映射为1、LOS为0；`unknown`表示参考不足或不确定，不映射为LOS。参考质量检查不是模型特征。

LR/RF读取当前五项特征，五网络读取同一卫星过去及当前32次观测。高C/N0仍可能是NLOS，LOS也可能存在多径。建筑、树木、车辆等具体遮挡物类别目前没有独立标签。

## 另一个任务：位置失准告警

比较 [data.py](../../src/navdiag/data.py) 的 `FEATURES`：卫星数、C/N0均值/最小值、HDOP、残差RMS和因果估计速度，共六项。一条样本是接收机历元，标签为：

```python
y = (horizontal_error_m > 10).astype(int)
```

误差由基线位置与合格独立参考比较得到。10 m是任务定义，不能替代NLOS标签，也不是达到的定位精度。缺少有效解或参考时无法构造这个标签，不能凭缺失把它写为0。

## 哪些字段不能成为输入

参考标签、参考坐标和参考误差包含答案，不进入学习特征。采集段、接收机、卫星ID和时间用于分组/排序；区域用于实验划分，不能让模型直接背记区域标签。两类允许输入分别由代码列表约束。

模型标准化器和缺失值填充只在训练数据拟合。验证/测试缺失测量保留真实含义，不以参考结果补造特征。

## 为什么按完整采集段划分

相邻观测共享卫星、运动与场景。如果同一条轨迹奇数行训练、偶数行测试，模型可能只是在识别近乎重复的场景。NLOS也不能把同一历元的不同卫星随意打散到不同集合。

| 集合 | 职责                             |
| ---- | -------------------------------- |
| 训练 | 学习参数，拟合填充与标准化       |
| 验证 | 选择模型、检查点、阈值和滤波设置 |
| 测试 | 评估已经确定的方案，不再调整     |

同次采集所有设备归在同一采集组。KLT双协议保持每对验证/测试段相同，跨区域移除目标区域训练段；完整段导致比例接近但不一定恰好6∶2∶2。

## 小练习

1. 对一条 `signal_label=unknown` 的观测说明它能否作为监督标签、能否提供已观察历史。
2. 一次位置误差为8.4 m，告警阈值10 m，其标签是多少？能否据此判断每颗卫星都是LOS？
3. 在两份特征列表中标出输入，再在一对 [固定划分](../../config/nlos_protocols.json) 中核对训练/验证/测试采集段。
4. 使用网页或公开报告阅读结果，不需要运行新的真实训练。合成学习入口见 [README](../../README.md)。

能用自己的话分别定义两种任务、说明标签来源和一处泄漏风险，就可以进入[第三课](03_models.md)。
