# 第四课：让模型调用代码取得证据

先运行 `navdiag ask "比较模型的 F1" --provider offline`，观察 answer、evidence 和 citation_check。offline 是一个便于读懂流程的规则基线，API 模式才让大模型选择工具。

## 一个问题的完整流向

用户问题和工具 schema 发给模型。模型返回例如 `compare_models({})`；Python 验证工具名和参数，读取本地报告，生成 `E1`。程序把函数结果回传给模型，模型最终引用 `[E1]` 组织回答。这里的数字由算法报告提供，而不是让语言模型凭印象估计。

OpenAI Responses 用 `function_call` / `function_call_output`，Chat Completions 用 `tool_calls` / `role=tool`。两者对应同一套 Python 工具，不能把协议字段直接混用。`tests/test_agent.py` 用模拟响应检查工具结果确实回传。

## 检索的作用与边界

八篇技术笔记用字符 n-gram TF-IDF 做检索，适合这个小型中英文知识库，不需要额外向量服务。每条笔记保留来源网址，回答可以把概念背景和本次观测证据分开。

低载噪比和大残差提示质量问题，但不能直接证明 NLOS。只有知识笔记而没有实验数据，也不能声称本次行程发生了某种故障。指标对照可以读取离线参考误差；在线片段工具不读取真实标签。

## 评测不能只看引用存在

30 题自动检查工具选择、证据 ID 与目标笔记检索。它们没有验证正文每个数字、因果解释或回答是否有用。实际 API 评测还需要人工检查正文数字的单位、指标和数据划分，以及模型是否越过证据边界。

练习：跟踪一次工具循环；把问题改为“自适应滤波是否提升”；检查模型是否忠实描述未超过固定滤波的结果；最后手工标注一个看起来有引用但结论不受证据支持的回答。
