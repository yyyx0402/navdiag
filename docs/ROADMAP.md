# 实现状态与后续路线

v0.3 的主线是 GNSS 逐卫星 LOS/NLOS 识别、区域实验和证据诊断。定位与误差超限告警保留为辅助任务。2026-10-11 用户要求完成 RAG 改进与测试后同步 GitHub，超参数搜索保持停止。

## 已完成的当前阶段

- Python 包、CLI、VS Code 调试入口、持久化模型、测试与发布检查。
- KLT 九段采集、三个日期：2,851 历元、45,228 卫星观测；同域与跨区域成对实验共六折。
- UrbanNav 尖沙咀、黄埔、旺角：5,671 原始历元、77,744 卫星观测，27,839 可评分静态建筑参考标签，其余 unknown。
- 冻结 KLT 模型和源验证阈值的外部迁移，以及 UrbanNav 一城区训练、另一城区验证、第三城区测试的六方向对比。
- MLP、CNN、LSTM、GRU、Transformer 五网络，与 LR、RF、C/N0 规则对照；不接入 MMTNet，不追加调参。
- 训练集拟合预处理、验证选模与阈值、完整采集段隔离、未知标签处理和错误分析。
- C/N0 观测分布审计、参考标签覆盖率、几何守卫、地理距离及源模型/输入指纹。
- 以真实 NLOS 为主的可折叠工作台：指标切换、区域热力图、覆盖率、混淆矩阵、阈值曲线、逐卫星卡片。
- 七个只读证据工具、十一篇原创笔记、39 问题的离线路由/引用基线；网页与 CLI 对齐当前实验目录。
- 单独的 GSDC 处理、WLS/稳健 WLS、位置失准分类与平面滤波；已撤回时间/高度错误导致的旧结果。

检查结果与限制集中在[进入 RAG 前的项目检查](PROJECT_REVIEW.md)。

## 下一阶段：RAG

1. 整理有来源、版本和段落位置的本地资料，解析与切分，保留当前 TF-IDF 对照。
2. 加入向量/混合检索，处理无关问题和检索无依据的情况。
3. 连接检索与只读实验工具：概念用文档，当前数值用报告，答案引用各自证据。
4. 建立检索和回答评测；将指标路由、引用 ID 检查与人工事实正确性评分分开。
5. 配置实际 API 后比较直接问答、检索问答和工具 Agent，记录成本与延迟。

目前已实现资料切分、本地 BGE 与关键词混合检索、来源行号、证据投影、缺少依据时的本地提示与检索评测；工具 Agent 保留由 LLM 选择工具和改写查询的能力。新增 29 个查询与旧 23 个查询分别保留结果和失败，39 项离线工具/引用回归通过。真实 GLM 解释质量、独立新问题集和重排器仍待验证，见 [RAG 记录](RAG_RETRIEVAL.md)。

## 后续研究，不混入当前完成声明

- 跨城市/跨设备、多日期独立留出与多种子稳定性，需要更多有可靠参考标签的独立行程。
- 同源 NLOS 识别到定位收益的闭环，需要匹配观测与参考定位，不能拼接无关 KLT/GSDC 样本。
- 遮挡物类型、动态车辆/树木、标签误差标定，需要相应参考传感器与核验。
- Zhang 2023 精确复现仍缺作者的完整特征、结构细节和 Aachen 对照数据；当前模型不能冒称复现。
- 完整 IMU 时间同步、姿态、杆臂标定与惯导，不由模拟 ENU 加速度接口替代。
