通过表示三个标准满足且未识别出重大额外错误，不是百分制正确率。引用编号存在也不说明引用支持该结论。测试集是少量开发者自编回归问题，后续修订已见到失败答案；不是盲测、代表性用户评估或对 GLM 本身的能力排名。

## 调用设置与耗时

本次仅验证“证据问答”，未验证多轮工具 Agent 或网页操作。评测在内存使用 8192 tokens 输出上限、120 秒超时和 `reasoning_effort=low`，没有改动用户保存的连接（仍为原输出上限和推理设置）。因此不能把本次结果当成原网页参数的完整等价验证；可在网页的输出设置中按需调整。

17 次调用耗时中位数 8.25 秒，范围 4.62–35.28 秒。供应商返回累计输入 122,262 tokens、输出 5,900 tokens、合计 128,162 tokens；其中报告的 reasoning tokens 为 52。未据此推算费用。证据较长的数值对比问题输入约 18k tokens，后续仍可压缩不相关的模型切片。

本地完整记录位于 Git 忽略的 `artifacts/glm_quality_*.json`，公开报告只包含问题、回答、审查和依据，不包含密钥、连接文件或模型思考正文。首轮未记录发送时的上下文校验；后两轮逐请求验证实际发送证据与准备阶段 SHA-256 一致。

## 复查

默认只准备问题和本地依据，零 API 请求：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_glm_answers.py --out artifacts/my_glm_check.json
```

真实调用必须显式选择本地连接并加 `--execute`，最多八次请求，遇首个错误停止；不自动重试。可用 `--cases G03 G05 G07` 限定范围。已有答案文件会阻止覆盖，需要使用新输出路径。连接 ID 从本机保存的连接选择，不把密钥写进命令或发布仓库。

下一次独立质量评估应新增未参与修订的真实用户问题，分别评估指标抄录、引用支持、过度推断、证据缺失和可读性，再考虑多次生成稳定性。此次证据足以确认当前连接和有依据的项目问答可用，尚不足以承诺所有回答可信。
