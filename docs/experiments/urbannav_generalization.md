# UrbanNav 未见城区泛化实验

已实际下载和处理尖沙咀 TST、黄埔 WP、旺角 MK 的公开记录，并完成冻结 KLT 模型外部测试和六个 UrbanNav 城区互斥实验。这里验证的是**同一城市中的未见城区**，不声称跨城市泛化，也不把静态建筑图参考标签称为人工逐卫星真值。代码、数据清单和汇总报告已在本地准备；尚未上传 GitHub。

[结果 JSON](urbannav_generalization_report.json)记录全部模型的 Precision、NLOS Recall、F1、混淆矩阵、阈值和逐区成绩。训练日志、模型与逐卫星预测保存在忽略的 `artifacts/urbannav_generalization`。

## 标签和特征分开

作者提供的是建筑仰角边界，不是现成的 NLOS 列。[UrbanNav 论文](https://ira.lib.polyu.edu.hk/bitstream/10397/109598/1/navi.602.full.pdf)说明每行三个 WGS84 坐标，加 0°～360° 的 361 个建筑边界仰角。我们使用独立 SPAN 参考位置与当天广播星历计算卫星方位角/仰角，再与附近建筑边界比较，来源明确为 `static_3d_sky_mask`。模型五项输入仍为 C/N0、SPP 仰角、归一化伪距残差、伪距变化率一致性和历史 C/N0 波动，均通过与 KLT 同一固定版本的提取器生成。

在查看模型得分前固定以下评分规则，工程范围未根据测试结果优化：

- 观测和位置参考按真实时间一对一匹配，最大允许差 50ms。三份数据最大实测差分别 6ms、2ms、1ms，GPS/UTC 的 18 秒偏差单独核对。旺角只有 2,312 个位置参考历元，余下观测标为 unknown。
- 只接受位置参考 Q≤2；这是质量筛选，不能据此保证每个位置达到某个厘米精度。质量较低的样本保持 unknown。
- 最近建筑网格不超过 2m，使用半径 3m 内最多四个网格和相邻方位角组成仰角包络，减少网格与水平杆臂误差的影响。
- 建筑图观察高度为 5m；与位置参考高度差大于 3m的样本不评分。没有擅自修正高程基准或假设已精确完成天线杆臂变换。
- 卫星仰角低于整个包络至少 5° 才标为 NLOS，高于至少 5° 才标为 LOS；包络边缘附近为 unknown。5° 是保守工程间隔，不是经人工标注校准的误差上界。
- 部分公开网格的 0°/360°值不相等，与论文的闭合描述存在差异。保留两个值进入包络。黄埔文件的一行坐标缺失被剔除，未补造坐标。缺星历、地平线以下或覆盖不足也不产生监督标签。

参考位置、建筑图、方位角、质量、区域 ID 和标签包络均不作为模型输入；模型预处理只拟合训练侧。未跟踪的卫星不在观测表中。这些标签只能表达静态建筑几何可见性，无法覆盖临时车辆、树木或复杂建筑模型误差，LOS 仍可含多径。标签覆盖率较低意味着本报告不能声称评估了全部路线上的 NLOS。

## 两个实验回答不同问题

**冻结 KLT 模型外部测试**：沿用已经完成的 `cross_region_klt3` 全部模型及各自源验证集阈值。源训练/验证只含 KLT1/KLT2 的完整采集段，源测试为 KLT3。TST/WP/MK 没有参与训练、验证、阈值或检查点选择。源验证集选中 LSTM，此次外部 RF 测试领先不触发重新选模。外部源模型和报告 SHA-256 在预测前冻结。

**UrbanNav 城区互斥实验**：一个完整城区采集用于训练，另一个用于验证，第三个用于测试；交换两个源城区的训练/验证角色，三个目标城区共六个方向。每折使用原始默认参数、种子 42、神经网络最多 30 轮，检查点和阈值只由该折另一个城区的验证数据确定。没有随机拆散卫星行，也没有为了凑 6∶2∶2 把同一路线拆入多个集合。此时没有每区多日期记录，不能构造独立采集层面的同域新实验。

六个方向复用三条轨迹，不是六个独立测试城区。先平均每个城区两个方向的指标，再等权平均三城区；宏平均 F1 不是平均 Precision/Recall 的调和平均。汇总报告的平均验证领先模型字段仅描述这些折，不对应一个额外训练并部署的全局模型；每折自己的验证选择才是该折的选模依据。

| 城区 | 冻结 RF F1 | 冻结 Transformer F1 | 互斥 RF F1 | 互斥 Transformer F1 |

整体 F1 是 RF 领先；旺角则 Transformer 的 F1 更高。不能只看总平均认为各地区一样，也不能把一个地区的领先归纳为稳定的模型优势。旺角只评估约五分之一的原始卫星记录，筛选对评价对象有明显影响。

**泛化测试不要求性能一定下降。**划分是否有效取决于目标区域是否留出、标签是否独立、模型和阈值是否没有使用目标测试信息，而不是能否观察到一个预期差值。跨数据集外部得分还受天线、标签方法、日期、NLOS 比例和未知标签排除影响，因此外部 F1 高于旧 KLT3 成绩不等于更好的普适泛化。UrbanNav 内部保持同接收机和同地图标签方法，仍无法分离城区与采集日期效应。当前没有独立驾驶重复，也没有可支持跨城市或显著性结论的置信区间。

## 复现与检查

对同城操作范围和 C/N0 域偏移的进一步审视见[分布审计](nlos_domain_audit.md)。共享测试段的固定 C/N0 规则必然得到相同成绩，不能用它的两列差值衡量泛化难度。

```powershell
python -m pip install -c requirements-lock.txt -e ".[dev,temporal,gnss]"
python scripts/fetch_urbannav.py
python tools/urbannav/prepare.py
# 需要已经完成的 KLT 双协议实验产物；只运行固定参数，不运行 tune-nlos。
python -m navdiag evaluate-nlos-regions
python -m navdiag serve --artifacts artifacts/navigation_demo --nlos-artifacts artifacts/klt_protocols --generalization-artifacts artifacts/urbannav_generalization
```

固定公开输入、字节数、SHA-256 和下载链接见 [源清单](../../config/urbannav_sources.json)。实验配置见 [固定计划](../../config/nlos_generalization.json)。已经存在的冻结计划与代码或输入不一致时程序拒绝覆盖，修改实验应使用新的输出目录。可公开结果摘要剔除了原始逐历元记录；绘图脚本只读取记录的成绩，不重新训练。

验证包含方位角四个方向和天顶几何、18 秒时间偏差拒绝、匹配重复/缺失、网格缺坐标、遮挡边界/高度/质量拒绝、城区泄漏检查、unknown 不进入分母、冻结阈值保持和网页接口。没有声称标签经过人工重新标注，也未验证分类带来的定位改善。

- [UrbanNav 作者公开仓库](https://github.com/IPNL-POLYU/UrbanNavDataset)及[时间/数据使用说明](https://github.com/IPNL-POLYU/UrbanNavDataset/blob/master/docs/GETTING_STARTED.md)。Hsu 等，2023，*Hong Kong UrbanNav: An Open-Source Multisensory Dataset for Benchmarking Urban Navigation Algorithms*，NAVIGATION 70(4)，DOI 10.33012/navi.602。
- [TST 普通 F9P 缺记录的作者讨论](https://github.com/IPNL-POLYU/UrbanNavDataset/issues/11)。三个区域一致使用 splitter。
- [NOAA 广播星历](https://ngs.noaa.gov/CORS/data.shtml)，[SatRef 原始 GNSS 数据](https://www.geodetic.gov.hk/en/rinex/downv.aspx)，[SatRef 文件规范](https://www.geodetic.gov.hk/common/data/satref/DataDict_RINEX.pdf)。GPS 与北斗星历来自采集当天，不能用六月或其他年份的星历代替。
- [NovAtel Waypoint 质量字段说明](https://docs.novatel.com/Waypoint/Content/PDFs/Waypoint_Software_User_Manual_D100513.pdf)。质量数用于筛选，不能代替独立误差验证。
- [GPL 独立适配器](../../tools/urbannav/README.md)复用固定版本外部提取器；主 Python 包不打包该源码。UrbanNav README 未给出明确数据再分发许可证，SatRef 有个人非商业内部使用限制，原始/派生表与模型均留在本地忽略目录。
