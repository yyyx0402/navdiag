## 仍不能声称已验证的内容

1. **跨城市泛化**：现有区域均在香港。新增三个较远城区有测试价值，但不能替代跨城市采集。
2. **稳定的模型优劣**：一随机种子，UrbanNav 每城区一段；六方向重复使用三个测试段，没有独立行程置信区间。
3. **完全可信的 NLOS 真值**：建筑图参考存在高度、杆臂和边界不确定性。旺角覆盖率 19.9%，分数只代表通过筛选的样本。
4. **高楼/树木/车辆类别**：当前只判 LOS/NLOS，遮挡物类型仍未知。
5. **定位收益与安全性**：没有把本批 NLOS 预测在同源定位任务上闭环验证；辅助模拟轨迹不能补充这项证据。
6. **论文精确复现**：当前逐卫星时序 Transformer 与 Zhang 2023 的跨卫星联合结构不同，[复现条件记录](research/zhang2023_reproduction.md)保留缺少数据与实现的事实。
7. **真实 API 回答质量**：已完成 GLM-5.3 的小型真实问答检查，保留首轮失败与复测；独立问题集与生成稳定性仍待验证，见[问答质量记录](experiments/glm_quality.md)。

这些内容不阻止开发 RAG；RAG 必须正确说明它们，不能生成不存在的实验结论。后续研究可以补数据、独立留出、同源定位与更精确标签，但本轮不通过重新调参或删困难样本制造改善。

## RAG实施与历史阶段安排

先围绕 NLOS 概念、数据集、预处理、模型比较和实验边界建立问答。输入使用项目原创文档和有明确引用的研究解读，文档保留 ID、版本、来源和段落位置；用户 PDF 只作为本地学习材料，不默认复制到开源仓库。数值问题通过只读工具读取当前实验报告，技术说明通过文档检索回答，两者在答案中分别引用。

实现顺序为：文档解析与切分 → 现有 TF-IDF 对照 → 向量/混合检索 → 引用与无证据拒答 → 问答评测。固定问题集分别检查概念、具体实验数值、任务混淆、缺少证据和过期结果；检索指标与最终回答的事实正确性分开评估。实际模型调用的延迟、费用和质量在配置 API 后记录。

已补上文档切分与准确来源行号、本地 BGE 语义/关键词检索、缺少依据时的本地提示、证据投影与单独检索评测，见 [RAG 实施记录](RAG_RETRIEVAL.md)。编码器和向量缓存留在本地；工具 Agent 可由 LLM 改写查询。2026-10-12 已使用用户指定的 GLM-5.3 连接验证实际回答并修正暴露的引用与上下文问题；重排器和独立新问题评测仍待完成。网页文案同步调整为诊断应用，保留折叠的数据与结果边界说明。用户授权在 RAG 测试后同步 GitHub；NLOS模型训练与调参继续停止；定位/告警默认实验依据新增授权运行。
