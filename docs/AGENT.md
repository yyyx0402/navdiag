# 诊断 Agent 的实现与验证

## 三层流程

1. 算法层从观测产生报告、预测和定位对照，保存不可随问答修改的实验产物。
2. 工具层读取限定实验目录，返回结构化结果与 `[E#]` 证据编号。本地 BGE 向量与 BM25/字符 TF-IDF 检索 11 条短笔记、9 份项目文档的 114 个段落和 7 篇研究摘要，保留章节、来源和准确行号；未准备编码器时回退关键词版。文献摘要另外标注作者、年份、DOI 与阅读范围。
3. 回答层选择离线基线或用户自定义模型连接。offline 采用简单规则和模板；证据问答把本地工具结果交给模型组织回答；工具 Agent 把 schema、函数调用结果送回模型，直到获得最终回答或用尽预算。

`trip_summary` / `segment_summary` 只读取观测和预测。`compare_models` / `compare_positioning` 是明确标记的离线参考评测。允许工具不包含任意读文件、执行命令或写入能力。

## 本地配置

优先在网页 **诊断助手 → 配置模型与 API** 保存自己的地址、模型与密钥。采用 Chat Completions 兼容格式，支持多个命名连接、本地无鉴权服务、模型列表获取和两种回答方式。配置保存在 Git 忽略的 `.navdiag/llm_connections.json`；密钥明文保存在本机，读取接口不回传密钥。改地址不能自动沿用旧 key；HTTP 重定向不被跟随。完整步骤与 CLI `--connection` 见[自选模型与 API](LLM_API.md)。

也可复制 `.env.example` 到 `.env` 配置 `NAVDIAG_PROVIDER=compatible`，自行设置模型与地址，`NAVDIAG_ANSWER_MODE=evidence` 使用证据问答。通用 `NAVDIAG_API_KEY` 只属于其声明的 provider；compatible 不会继承其他服务的专用密钥。历史 OpenAI Responses / DeepSeek 适配器保留兼容现有 CLI 配置，网页主入口不预选这些模型。API 问题和证据发往所选地址；仅在点击分析或 CLI 问答时调用推理。

工具循环最多 5 轮、每轮 6 个调用，由 LLM 选择工具和改写检索词。新连接默认输出上限 4,096 tokens、单次超时 90 秒，已有连接保留原设置；历史环境配置沿用 1,500 tokens / 60 秒。证据问答最多一次请求，不需要工具调用支持；完全没有相关依据时本地说明缺少资料，标记未调用模型。API 失败给出错误，不自动回退并假装已调用模型。

接口依据：[Ollama 兼容接口](https://docs.ollama.com/api/openai-compatibility)、[DeepSeek Chat Completion](https://api-docs.deepseek.com/api/create-chat-completion/)。实际模型 ID 与可用能力由所选服务决定。

## 固定评测

`resources/agent_cases.json` 的 39 个问题覆盖模型/定位/数据/片段/技术概念及当前 NLOS 协议。`evaluate-agent` 逐题保存回答、工具证据、usage、延迟和以下检查：

- 是否调用预期工具。
- 是否引用已存在的证据 ID，是否包含伪造 ID。
- 工具证据是否包含真实/模拟来源标记。
- 检索内容标为 knowledge，并携带条目 ID 与来源；不随定位分支被误标为模拟观测。
- 指定问题的目标知识条目是否进入前五条检索结果。

历史模拟与真实定位实验的 33 问题基线均通过。本轮使用当前 KLT 协议和 UrbanNav 泛化目录，offline 通过扩展后的 39/39。API 的两种协议用模拟供应商响应验证；本机已配置连接，但尚未运行真实模型评测。39/39 不能解释为答案事实正确率、根因推理正确率或大模型能力。

要报告实际 LLM 成绩，需要用 `--connection 连接ID` 运行同一题集，再人工核对数字对应的指标/单位/划分，数据边界、未知结论和用户问题是否被回答。只检查 `[E1]` 存在并不能证明正文每个数字受证据支持。

## 独立遮挡工具

新增 compare_nlos，读取同级 klt_nlos 报告或网页指定的伴随实验目录，明确为卫星级 LOS/NLOS 离线参考评测。定位风险与遮挡报告可以分别来自模拟和真实数据，证据各自保留来源。未加载时返回 unavailable，不把原误差分数充当遮挡成绩。该工具无任意路径参数。

当前默认优先读取同级 `klt_protocols` 套件；没有该套件时才回到历史 `klt_nlos`。网页传入用户选择的折目录，CLI 可用 `--nlos-artifacts` 明确指定套件或历史目录；套件默认取首个实验。`--generalization-artifacts` 指定新城区汇总。证据同时携带单折指标、双协议和泛化对照，明确固定规则在共享测试集上必然相同。

网页的“问答任务”以及 CLI 的 `--task-context satellite_nlos` / `position_error` 传递任务上下文。泛泛的“比较模型 F1”在 NLOS 上下文中读取卫星实验，避免引用辅助模拟告警分数；单折数据划分只描述当前折。明确询问泛化时，读取新城区报告并保留覆盖率与同城限制。模型训练历史不塞进数值对比工具，但完整历史仍保存在本地报告。

当前检索管线、同语料基线比较与失败查询见 [RAG 检索评测](RAG_RETRIEVAL.md)。实验数值优先读取当前产物；文档用于解释方法。本地向量检索已经评测，实际 GLM 回答质量仍未验证。
